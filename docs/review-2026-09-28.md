## 審查發現及修正

- 原轉錄器在字串與註解上直接施行正則替換，且改寫 import 時無法保留複數引入、相對路徑與 future imports。現以符節位置改動原文，代理體保存可逆改動紀錄，整庫閱覽體保存名稱對照與位置。
- 原駢文排版從抽象語法樹重建程式，遺失註解、空白、完整簽名、非同步與例外控制；逆轉更會猜成固定的反溯接收者。現駢辭供閱覽，完整碼卷供還原，校驗不符即停止。
- 編輯器另藏一份 JavaScript 正則轉錄器，與 Python 核心分歧，沒有解賦入口。現共用 Python 標準輸入介面；Markdown 右鍵可解賦或直接還原 Python，轉換失敗或文卷在等待期間修改時不覆寫。
- 原套件在 editor/title 註冊三個頂端按鈕。0.1.6 移除此入口，保留三個右鍵指令；包內 manifest、程式及圖示已比對，套件已於本機安裝。
- 原代理只解開最外層參數。現共用遞迴解包，保留無代理容器的身分，考校涵蓋巢狀 dict/list/tuple 與循環容器。
- 原 tests 全被忽略，乾淨 clone 不會獲得文件聲稱的考校。現收錄核心與無損考校，參考來源和生成結果仍依使用者要求忽略。
- 原聲稱 Python 3.8 卻使用 3.9 才有的 ast.unparse。完整辨識 f-string 內名稱需 3.12 的符節介面，故明示 Python 3.12 以上。
- 新整庫搬卷拒絕來源／目的地重疊、既有目的地、封卷路徑穿越連結與檔名碰撞；錯誤時移除當次未完成的暫存輸出，不碰來源。

## 證據範圍與限制

- 以上證明原碼、資料與所列檔案結構能完整還原，不證明任意翻譯後專案可直接由 Python 執行。整庫閱覽體須解碼後執行；未執行參考專案，也未進行本機機器學習訓練或評估。
- 已知名稱取詞典文言，未知名稱取可逆漢字代號，不宣稱自動作出自然的文言語義翻譯。Python 保留字與軟關鍵字、字串、註解、檔名，以及 .pyx／C／圖片等非 Python 檔案原樣保留。
- CPython 與 Black 包含故意錯誤的語法、控制字元與編碼素材；這些以文字搬卷，不宣稱可執行。原始位元組仍經相同比對。
- Git 歷史、時間戳、硬連結關係及延伸屬性不在還原契約內。
- 逐字還原要求保留封卷與完整碼卷；修改碼卷時拒絕還原，舊式沒有完整碼卷的駢文須重新產生。單卷正文修辭可以修改；整庫封卷另驗證整份輸出。
- 舊式手寫代理體的逆轉無原文紀錄，不能承諾逐字還原。既有代理體入口僅保留已支援的通用詞律，不宣稱任意庫的直接執行相容性。
